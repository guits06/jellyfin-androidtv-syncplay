# Architecture & Optimization Decisions (`DECISIONS.md`)

Format: `- **[Area]** Decision — Reason | Rejected alternative`

- **[TV Environment]** Disabled system ad/telemetry packages on Chromecast HD (`com.google.android.adservices.api`, `com.google.android.ext.adservices.api`, `com.google.android.federatedcompute`, `com.google.android.ondevicepersonalization.services`, `com.android.tv.feedbackconsent`) via `pm disable-user --user 0` — Frees background CPU/RAM contention on 1.4 GB low-RAM target without affecting streaming apps or system stability | Leaving ad/personalization services running or disabling core GMS/Tailscale/Play Services.
- **[SyncPlay Architecture]** Model playback/SyncPlay event origins explicitly (`USER_LOCAL`, `REMOTE_SYNCPLAY`, `INTERNAL_PLAYER_TRANSITION`) instead of transient boolean `isHandlingRemoteCommand` — ExoPlayer transitions (`onIsPlayingChanged`, `STATE_BUFFERING`) execute asynchronously after `controller.play/pause/seek` returns, so synchronous booleans leak loopback events to the server | Increasing arbitrary coroutine delay timers around a boolean flag.
- **[SyncPlay Track/Burn-In Switching]** Handle audio/subtitle/burn-in stream rebuilds via an internal stream-reload transition (`INTERNAL_PLAYER_TRANSITION`) that preserves intended play/pause state and target SyncPlay position without reporting user `Stop`/`StartPlayback` — Changing subtitles to `ENCODE` (burn-in) or transcoding audio must appear transparent to other SyncPlay participants | Allowing `stop()` + `play()` to send `Stop` and `SetNewQueue` requests or force `PLAYING` when paused.
- **[UI Migration Strategy]** Replace individual Leanback Fragments (`HomeFragment`, `BrowseGridFragment`, `FullDetailsFragment`, `SearchFragment`) incrementally inside `DestinationFragmentView` using pure Jetpack Compose (`androidx.tv:tv-material:1.1.0`) — Preserves 100% of existing `NavigationRepository` destinations, arguments, and deep-links without risky single-shot rewrites | Keeping Leanback `RowsSupportFragment` wrappers (`AndroidFragment`) or rewriting all fragments into a monolithic graph at once.
- **[Image & Blur Pipeline]** Enforce global Coil `allowRgb565(true)`, 12% RAM / 96 MiB disk cache caps, exact pixel-bounded `Size`, and replace `Modifier.blur(10.dp)` in `AppBackground` with `drawWithCache` gradient scrims — Cuts bitmap memory by ~50% on 1080p TVs and eliminates heavy `RenderEffect` overdraw frame drops on Chromecast HD | Unbounded `ARGB_8888` image decoding and real-time GPU Gaussian blur.
- **[Hero Billboard Focus]** Debounce D-pad hero backdrop updates by `350ms` and animate card focus solely via GPU `graphicsLayer` springs (`CinemaMotion.FocusSpring`) — Prevents image decode/recomposition churn while rapid-scrolling rows on modest TV CPUs | Immediate per-focus backdrop swaps or layout-size animations.
- **[Native C Image Analysis (`libcinefast.so`)]** Added a tiny `-O3` C NDK library (`app/src/main/cpp/cinefast.c` + `CineFastNative.kt`) using NDK 24 (`ndkVersion = "24.0.8215888"`, CMake 3.18.1) to extract dominant darkened surface/accent tints from `64x64` `RGB_565`/`ARGB_8888` samples in ~0.15ms on CPU instead of GPU `RenderEffect` blur — Eliminates Mali-G31 fragment-shader stalls and extra `RenderTarget` allocations | Jetpack Compose real-time GPU blur or Java/Kotlin heap-allocating `Palette` computation.
- **[Zero-Recomposition Focus & Overdraw]** Replaced `mutableStateOf(isFocused)` + `tv.material3.Surface` on cards/chips/buttons/tracks with `Animatable(0f)` read strictly inside `graphicsLayer` + `drawBehind`/`drawWithContent`, removed duplicate `.focusable()` before `.clickable()` (which swallowed `DPAD_CENTER` key events), overlaid `CinemaNavigationRail` instead of resizing a `Row(weight(1f))` sibling, and suppressed legacy `AppBackground` on Compose fragments — Eliminates recomposition storms, full-screen relayout on Rail hover, and double-backdrop overdraw | Material `Surface` container state animations or width-animated `Row` navigation rail.
- **[Disc, Library Grid & Music Hub Compose Screens]** Migrated `BrowseGridFragment`, `BrowseViewFragment` (non-LiveTV libraries), `CollectionFragment`, `GenericFolderFragment`, `ItemListFragment`, `MusicFavoritesListFragment`, and `AudioNowPlayingFragment` to M3 Expressive Compose screens backed by lightweight `ItemRepository.browseFields` — Adapts movies, anime, libraries, discs/albums, playlists, and Now Playing uniformly with instant D-pad filtering | Maintaining Leanback `VerticalGridSupportFragment` / XML bindings alongside Compose Home.
- **[Media Detail & Search Compose Cutover]** Wired `FullDetailsFragment` (when `ChannelId`, `ProgramInfo`, and `SeriesTimer` are absent) to pure Compose `MediaDetailScreen` + `MediaDetailViewModel` with inline expandable pre-playback Audio/Subtitle track pickers, season/episode tabs, discography, filmography, and SyncPlay launch, while keeping Leanback fallback solely for LiveTV schedule timers; replaced Leanback `RowsSupportFragment` inside `SearchFragment` with pure Compose `SearchScreen` — Unifies every media detail page (movies, series, anime, episodes, artists, actors, boxsets) and search in zero-recomposition M3 Expressive UI | Rewriting rarely used LiveTV series timer dialog presenters or keeping Leanback `SearchSupportFragment` chrome.
- **[Player SyncPlay Status HUD]** Updated `CustomPlaybackOverlayFragment` to observe both `currentGroup` and `groupState` so the player OSD badge displays live localized SyncPlay status (`PLAYING`/`WAITING`/`PAUSED`/`IDLE`) and color-coded tint (`#2E7D32`/`#EF6C00`/`#455A64`) — Gives immediate sync visibility during playback without modifying core SyncPlay controller state machine logic | Replacing the entire ExoPlayer Leanback OSD layout or adding polling timers.
